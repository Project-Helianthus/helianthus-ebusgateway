# Changelog

## Absence, admission and energy diagnostics without a controller

The debug regulator absence state (`semantic_regulator_state` on `/debug/vars`) starts at the new value `UNKNOWN` (not yet evaluated) instead of `PRESENT`. The first regulator recheck moves it to `PRESENT` when the regulator capability is `PRESENT` and to `ABSENCE_GRACE` otherwise, with the grace period measured from that recheck, so `ABSENT` is reached at the same moment as before (six minutes of polling with the defaults). The transition log and `semantic_regulator_transitions_total` report `UNKNOWN` as the source state of that first transition. `vaillant_regulator_capability`, the grace period and the controller search are unchanged.

With an explicitly configured startup source on a source-selection-capable transport, the startup scan no longer requires a coherent B524 root when the root confirmation of a pass finds none and the product catalog classifies every Vaillant identity in the inventory as a non-controller. Active confirmation then decides: a device that answered the scan admits the source on that pass and the scan logs `startup scan: root confirmation not required: inventory has no regulator identity; active confirmation=<bool>`. Root confirmation is waived on the first pass whose inventory holds only non-controller identities, so on a bus without a controller the explicit source is admitted on the first pass, without the admission failure and the second pass of before; a controller that answers nothing in that first pass gets no second startup pass and is found by semantic discovery, the background scan or passive insertion. The passed probe starts the runtime-state revalidator for the explicit source, which sends directed identification reads (service 07 04) to the cached runtime-state members, one cycle at once and then every 15 minutes; no write and no address claim is added. An inventory with a regulator identity, or with a Vaillant identity that has no readable serial or an uncatalogued part number, still requires root confirmation. Source-selection admission (the add-on default) and other transports are unchanged.

GraphQL `energy_totals`, the MCP energy totals tool and the energy plane of the MCP semantic snapshot are null until the energy merge store has accepted its first point, instead of a projection of 0 values with provenance `none`. From the first accepted point on the per-slot projection, its `0`/`none` placeholders and its freshness metadata are unchanged, also after the store prunes points. Energy is not persisted, so after every gateway restart the plane is null until the first energy refresh (up to 5 minutes with the defaults). Merge rules, provenance values and retention are unchanged; the Home Assistant integration already handles a null energy plane and keeps the last valid totals.

The controller-less site scenario, the poller, startup scan and energy tests and the reduced run sheet cover the changes. The startup admission change is transport work: the affected transport rows must be re-run in the consolidated hardware session, and the affected release evidence must be renewed before the final bill of materials freeze.

## Controller search at the discovery interval once the regulator is absent

On a bus where this process has never discovered a B524 root, once the regulator absence state is `ABSENT` the semantic state and configuration tasks no longer run their fallback B524 root discovery pass. Root discovery then runs only from the discovery task at the configured discovery interval (10 minutes by default) and from event-driven refreshes: a registry inventory change seen by the regulator recheck, passive address insertion and passive promotion. The suspension logs `semantic_discovery_fallback_suspended regulator_state=ABSENT discovery_interval=<interval>` once each time it starts. With the periodic discovery task disabled (a discovery interval of zero or less) nothing is suspended and the per-minute search stays as before. While suspended, the state and configuration ticks still read the boiler-class heat source from the registry, so a heat source identified after `ABSENT` gets its status reads on the next tick; the FM5 interpretation is still refreshed by the energy task (5 minutes). On a bus without a controller the root probes drop from 120 to 33 calls in the first 30 minutes of polling, and an identified internet module is probed at the discovery interval like any other candidate. `ABSENT` alone does not mean there is no controller: a controller registered without a serial, with a part number missing from the product data, or with the product data unavailable also reaches it, so a process that has discovered a root once keeps the per-minute recovery after a failed discovery pass. Before `ABSENT`, with a known controller, and with a known controller that has no zone, the per-minute rediscovery is unchanged. A controller that becomes reachable after `ABSENT` on a bus that never had one, without passive observation or a registry change, is found within one discovery interval instead of one minute. No configuration switch is added. The controller-less site scenario, the poller tests and the reduced run sheet cover the change; the affected release evidence must be renewed before the final bill of materials freeze. The same applies during a gateway process that has not discovered a root yet, for example after a restart while a controller that the product data does not classify is still unreachable when the absence state is reached: that controller is then found at the next discovery tick or event-driven refresh, not within a minute.

## Site profile without a system controller

An offline acceptance scenario covers an eBUS that carries a heat source and the vendor's internet module but never a system controller. It runs the production startup scan, registry scan, B524 root probe, semantic poller, read scheduler and poll schedule over a recording synthetic bus on a simulated clock that starts at process start. It asserts the startup phases against the boot-live deadline, the root discovery frames and attempts, the native refresh spacing of the heat-source registers, the published streams and the regulator-absence signal. The [reduced run sheet](docs/testing/site-without-controller-run-sheet.md) for the hardware session at such a site removes the controller rows and names the remaining ones.

Runtime behaviour is unchanged. The semantic poller's root probe now sends through the poller's existing frame seam, its read-retry, post-read and probe back-off waits go through one pause hook with the same durations, and the semantic read scheduler gains `SetClock`, so the scenario runs the production probe and read cache on its clock. The gateway binary changes, so affected release evidence must be renewed before the final bill of materials freeze.

## Catalog spelling in the acceptance catalog and modbusreg adoption

The acceptance catalog package drops the work-item prefix and uses the catalog spelling: `Catalog`, `ReadCatalog`, `Signature`, `ReadSchema`, `ReadReport`, `ValidateReport`, `MaxBytes`, `Row`, `Category`, `Transition`, `Identity`, `Review`, `Record` and `Report`, whose version field is `CatalogVersion`. The report JSON key `catalogue_version` and the schema text are unchanged; they change with the acceptance report format. The catalog documents move to `docs/testing/hardware-acceptance-catalog.md` and `docs/testing/hardware-acceptance-catalog-v1.json` with unchanged catalog data, versions and ledger signatures. There is no alias or compatibility layer. `python3 scripts/rename_acceptance_catalog.py` reproduces the Go rename offline and its `--check` mode lists any remaining old name, spelling or file name.

The modbusreg pin moves to the main-branch revision with the catalog spelling. The Huawei PV publication admits a child only on the renamed `Catalog` decision with the `HuaweiSUN2000CatalogSelected` outcome. Withheld Huawei children now report the reasons `catalog_not_selected` and `catalog_ambiguous` in the Huawei instance status tools and the Portal instance diagnostics, and the Huawei observation evidence digest covers the `catalog` key of the native child observation. Admission, native records, retained last-good state and other wire values are unchanged. The gateway binary changes, so affected release evidence must be renewed before the final bill of materials freeze.

## canbusreg provider behavior names

The canbusreg pin moves to the main-branch revision with the provider export renames, the Growatt BMS provider error texts and the exported API documentation. The Growatt project configuration, provider, LINK and PCS runtimes, CLI and their tests use the behavior names `SelectionSpec`, `SelectionSpecValue`, `SelectionGroup`, `ReplayInput`, `LINKInput`, `MeasurementGate`, `VectorSnapshot`, `Observation`, `Provider`, `NewLINKProvider`, `NewPCSProvider`, `ProjectProviderSnapshot`, `SelectionNativeIndication` and `ConfirmNativeSelection`; the gateway receive source implements `ProjectProviderReceive`. There is no alias or compatibility layer. `python3 scripts/rename_can_provider_references.py` reproduces the rename offline and its `--check` mode lists any remaining old name.

Native records, admission, field ages, retained last-good state and wire values are unchanged. The gateway binary changes, so affected release evidence must be renewed before the final bill of materials freeze.

## Coordinated public naming adoption

Owned GraphQL types, roots, fields and arguments use snake_case. CamelCase twins are removed. Zone observations use zone_room_temperature and zone_room_humidity. The selector-dependent target_temp_c remains provisional pending resolution of its manual, heating and cooling source selection.

MCP registered tool names join namespace tokens with underscores. The legacy ebus.invoke and ebus.devices routes are withdrawn. Pairing status remains registered. Versioned invoke intent, permission, dangerous-operation and replay requirements are preserved.

Circuit setters adopt the six selector-qualified names in the naming inventory. The unsupported frost-protection float writer is withdrawn: frostProtC and frost_prot_c perform no dispatch. Raw provisional observations remain. Other setter vocabulary without approved identity-qualified targets remains provisional.

SemReg thermal members adopt humidity, temperature_setpoint and dhw_temperature_setpoint. eeBUS structural output uses use_cases while opaque native evidence is preserved. Huawei status replaces device_status; energy_accumulated remains provisional. The bounded temperature metric names use constant celsius labels and semantic evidence age uses a constant seconds label. Numeric conversions and retained slot ownership remain unchanged.

Affected security, hardware and candidate evidence must be renewed before release. Full repository gates, affected transport/conformance, consumer coordination, the no-Matter build and independent review remain shipping requirements.
