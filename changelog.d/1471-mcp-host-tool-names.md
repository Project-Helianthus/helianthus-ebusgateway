## Move the two experimental MCP tools to host tool names and write the namespace plan

The MCP tools `helianthus_experimental_leaf_promotion_capture` and `helianthus_experimental_m8_source_state_get` are now `helianthus_v1_leaf_promotion_capture` and `helianthus_v1_source_state_get`, without an alias: the previous names are unknown tools. Their behaviour, schemas and authorization boundaries are unchanged. A namespace plan page, `docs/architecture/mcp-namespaces.md`, gives every namespace one owner (protocol-native `ebus_v1_`, `eebus_v1_` and `modbus_v1_` tools, protocol-neutral `semantic_v1_` tools, host `helianthus_v1_` and `helianthus_runtime_` tools) and lists every registered tool with its owner namespace and target name; the family-keyed `ebus_v1_semantic_*` reads move with the retrieval work of #1540. A test rejects a registered tool outside the plan or with an `experimental` name, and a tool name the gateway dispatches on that is not registered. The generated MCP tool inventory shows the new names. The gateway binary changes.
