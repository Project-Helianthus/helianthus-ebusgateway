## Split startHTTPServer into per-surface registration and server lifecycle

`startHTTPServer` keeps its signature and becomes the server-lifecycle orchestrator: validation, Portal clients, provider composition, MCP surface, core routes, Portal surface and listener. The Portal surface and the MCP surface are built by named functions in their own files, in the same order: `newGatewayHTTPPortalOptions` builds the Portal options from named registry, semantic snapshot, projection, bus and raw Modbus audit functions, and `installGatewayHTTPMCPSurface` installs the Vaillant B503 tools and GraphQL provider, the responder capability and the schedule and configuration writers. Both surfaces reject a missing required input before installing anything. Routes, handlers, metric names and existing errors are unchanged. The gateway binary changes.
