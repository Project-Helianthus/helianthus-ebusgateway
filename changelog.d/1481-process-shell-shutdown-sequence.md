## Give the process shell its resources and an explicit shutdown sequence

The process shell acquires its resources in the same order through `gatewayProcessShell` (run configuration, semantic hub preflight, release checker, synchronized evidence sidecar, Portal contribution registry, runtime state, Portal configuration, stale eeBUS operator socket clean-up, managed sidecars, eBUS driver, runtime control, retained EVSE owner, then the eeBUS adapter, admin handler and evidence configuration) and releases them through a named shutdown sequence that runs last in, first out and that a test asserts end to end; before, the order was pinned only as source text over a stack of deferred statements. `runGatewayLifecycle` registers the M2M sidecar and its own releases in the same sequence, and the redaction of file-sourced Modbus endpoints still applies last. The order, the joined shutdown errors and the log lines are unchanged. The gateway binary changes.
