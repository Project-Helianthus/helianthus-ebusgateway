## Specify the mux states, events and transition table in tests and check the handlers against it

The AdapterMux states, events and transition table are specified in test code: thirteen named states built from the arbitration phase (idle, bids queued, START in flight asynchronously or through the blocking call, owned by the gateway with an active transaction or in its idle grace, owned by a session, fenced until SYN with its recovery kind, arbitration held for an out-of-step adapter) and the stale-response absorb, blocking-call and resynchronization-SYN barriers; thirteen events (SYN, received symbol, bid, STARTED for the selected or another source, FAILED, the START deadline, absorb debounce, idle grace, ownership limit and abandon watchdog timeouts, session close and adapter reset); and one row for every state and event pair with the next state and the ordered effect kinds, or an explicit row stating that the event cannot occur in that state. Every valid pair is checked against the current handlers through the characterization harness. Test-only: the gateway binary is unchanged.
