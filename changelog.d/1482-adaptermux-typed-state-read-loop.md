## Introduce the typed mux state and transition function and route the read loop through events

The AdapterMux gets a typed state derived on demand from its fields (the arbitration phase, the recovery kind, the absorb, blocking-call, out-of-step hold and resynchronization barriers, the START in flight, the owner, the queued bidders, the deferred gateway loser, the retired selection, the gateway's expected echo with its terminator provenance and whether an owner's telegram is live), an event type and one transition function, which holds the rule saying which events can occur in which state and takes the read loop's STARTED and FAILED decisions. The read loop translates each stream item or read error into an event and dispatches it to one method per kind: read failure with blackhole detection, STARTED, FAILED, RESETTED and symbol. The state-model table now runs over the production state and transition function and keeps apart the queued bidder, the structural terminator echo, the initiator predicate (a phantom FAILED event) and the live telegram. `doc.go` describes the states and events. Wire behaviour, timing and effect order are unchanged; the gateway binary changes.
