## Publish the boiler registers under their docs-ebus names

The boiler state, configuration and diagnostics fields that a single B509 register feeds are published under their docs-ebus register names in GraphQL (`boiler_state`, `boiler_config`, `boiler_diagnostics`), in the MCP boiler snapshot and in the Portal boiler snapshot. The former names are no longer published; there is no alias, no duplicate field and no unit suffix: the GraphQL description of each field states its unit.

- `boiler_state`: `flow_temperature_c` → `flow_temperature` (°C), `water_pressure_bar` → `water_pressure` (bar), `diverter_valve_position_pct` → `diverter_valve_position` (%), `fan_speed_rpm` → `fan_speed` (rpm), `target_fan_speed_rpm` → `fan_speed_setpoint` (rpm), `ionisation_voltage_ua` → `flame_ionization_current` (µA), `dhw_water_flow_lpm` → `dhw_water_flow_rate` (L/min), `storage_load_pump_pct` → `storage_loading_pump_level` (%), `modulation_pct` → `modulation_setpoint` (%), `primary_circuit_flow_lpm` → `primary_circuit_flow_rate` (L/min), `flow_temp_desired_c` → `flow_temperature_setpoint` (°C), `dhw_temp_desired_c` → `dhw_temperature_setpoint` (°C) and `state_number` → `boiler_state_code`.
- `boiler_config`: `flowset_hc_max_c` → `maximum_heating_flow_temperature_setpoint` (°C), `flowset_hwc_max_c` → `maximum_dhw_flow_temperature_setpoint` (°C), `partload_hc_kw` → `heating_partial_load_power` (kW), `partload_hwc_kw` → `dhw_partial_load_power` (kW), `installer_menu_code` → `central_heating_pump_mode`, `phone_number` → `installer_phone_number` and `hours_till_service` → `service_time_remaining` (h); the Portal publishes the first four.
- `boiler_diagnostics`: `central_heating_hours` → `central_heating_operating_time` (h), `dhw_hours` → `dhw_operating_time` (h), `central_heating_starts` → `central_heating_start_count`, `dhw_starts` → `dhw_start_count`, `pump_hours` → `pump_operating_time` (h), `fan_hours` → `fan_operating_time` (h), `deactivations_ifc` → `fire_control_deactivation_count` and `deactivations_templimiter` → `temperature_limiter_deactivation_count`.

Where the docs-ebus register row carries an open question, the GraphQL description says the name is provisional. `central_heating_pump_active`, `external_pump_active`, `circulation_pump_active`, `gas_valve_active`, `flame_active`, `dhw_demand_active` and `heating_switch_active` already carried their docs-ebus names. `return_temperature_c`, `dhw_temperature_c`, `dhw_target_temperature_c`, `dhw_operating_mode`, `heating_status_raw` and `dhw_status_raw` keep their names: no single B509 register feeds them. Values, value types, units, the register reads and the setter keys are unchanged. The record `graphql/testdata/register_derived_names.json` lists every boiler field with its selector, its docs-ebus name and the gateway's previous spelling, and the unmapped fields with their reason; the GraphQL, MCP and Portal contract tests reject the previous spellings. Consumers read the new names in the same wave. The published GraphQL, MCP and Portal names change, so the gateway binary changes.
