## Publish the remaining system registers under their docs-ebus names

The system configuration and state fields that still used a gateway spelling are published under their docs-ebus register names in GraphQL (`system_state`, `system_config`), in the MCP system snapshot and in the Portal system snapshot. The former names are no longer published; there is no alias and no duplicate field.

- `system_state` (B524 OP02 GG00): `outdoor_temperature_avg24h` → `outdoor_temperature_daily_average` (RR0095), `maintenance_due` → `maintenance_active` (RR0096; provisional, two readings of the register are unresolved), `hwc_cylinder_temperature_top` → `dhw_cylinder_top_temperature` (RR009D) and `hwc_cylinder_temperature_bottom` → `dhw_cylinder_bottom_temperature` (RR009E).
- `system_config` (B524 OP02 GG00): `alternative_point` → `heating_outdoor_alternative_temperature_limit` (RR0022), `dhw_bivalence_point` → `dhw_outdoor_bivalence_temperature_limit` (RR0001) with its bound `dhw_bivalence_point_bound` → `dhw_outdoor_bivalence_temperature_limit_bound` (GraphQL and MCP), `hc_emergency_temperature` → `heating_flow_temperature_setpoint_maximum_at_heat_pump_fault` (RR0026), `hwc_max_flow_temp_desired` → `dhw_flow_temperature_setpoint_maximum` (RR0046) and `installer_phone` → `installer_phone_number` (the join of RR006F and RR0070; GraphQL and MCP, the Portal does not publish it).

Values, value types, units, write bounds and the register reads are unchanged, and so are the setter keys. `system_off` (RR0007) keeps its name: docs-ebus still carries a provisional placeholder for the register until helianthus-docs-ebus#1145 settles its final name. The record `graphql/testdata/register_derived_names.json` lists the renamed fields with the gateway's previous spelling of each; the GraphQL, MCP and Portal contract tests reject those spellings as well as the docs-ebus previous names. Consumers read the new names in the same wave. The published GraphQL, MCP and Portal names change, so the gateway binary changes.
