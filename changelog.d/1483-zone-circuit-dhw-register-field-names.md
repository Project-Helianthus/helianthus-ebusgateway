## Publish the zone, circuit and hot-water registers under their docs-ebus names

The zone, circuit and hot-water fields that one B524 register feeds are published under their docs-ebus register names in GraphQL (`zone_state`, `zone_config`, `circuit_state`, `circuit_config`, `dhw_state`, `dhw_config`), in the MCP zone, circuit and hot-water snapshots and in the Portal semantic snapshot. The former names are no longer published; there is no alias and no duplicate field. Where the former name carried a unit, the GraphQL description of the field states it.

- `zone_state`: `special_function` → `zone_special_function_mode` and `valve_position_pct` → `zone_valve_position` (%).
- `zone_config`: `quick_veto_setpoint` (MCP `quick_veto_setpoint_c`) → `zone_room_temperature_setpoint_at_quick_veto` (°C), `quick_veto_duration` (MCP `quick_veto_duration_h`) → `zone_quick_veto_time` (h), `holiday_start_date` → `zone_holiday_start_date`, `holiday_end_date` → `zone_holiday_end_date`, `holiday_setpoint` (MCP `holiday_setpoint_c`) → `zone_room_temperature_setpoint_at_holiday` (°C), `holiday_start_time` → `zone_holiday_start_clock_time` and `holiday_end_time` → `zone_holiday_end_clock_time`; the Portal publishes none of these.
- `circuit_state`: `pump_active` → `circuit_pump_unknown_8`, `mixer_position_pct` → `circuit_mixer_position` (%), `flow_temperature_c` → `circuit_flow_temperature` (°C), `flow_setpoint_c` → `circuit_flow_temperature_setpoint` (°C), `humidity` → `circuit_room_humidity` (%), `dew_point` → `circuit_dew_point_temperature` (°C), `pump_hours` → `circuit_pump_operating_time_total` (h) and `pump_starts` → `circuit_pump_start_count_total`.
- `circuit_config`: `heating_curve` → `circuit_heating_curve_factor`, `flow_temp_max_c` → `heating_circuit_flow_temperature_setpoint_maximum` (°C), `flow_temp_min_c` → `circuit_flow_temperature_setpoint_minimum` (°C), `summer_limit_c` → `heating_circuit_outdoor_temperature_limit_maximum` (°C), `room_temp_control` → `circuit_room_temperature_influence_mode` and `cooling_enabled` → `circuit_cooling_enabled`.
- `dhw_state`: `current_temp_c` → `dhw_temperature` (°C) and `special_function` → `dhw_special_function_mode`.
- `dhw_config`: `operating_mode` → `dhw_operating_mode`, `target_temp_c` → `dhw_temperature_setpoint` (°C), `holiday_start_date` → `dhw_holiday_start_date` and `holiday_end_date` → `dhw_holiday_end_date`; the Portal publishes the first two.

Derived fields keep their names: among them the zone room temperature and humidity, `hvac_action`, the zone `operating_mode`, `preset` and `target_temp_c`, `quick_veto`, `quick_veto_expiry`, `calc_flow_temp_c` and `overrun_active`. With this slice no register-derived published name differs from its docs-ebus name: the `pending` list of `graphql/testdata/register_derived_names.json` is empty, a GraphQL contract test keeps it empty, and the MCP and Portal contract tests accept only the recorded name of each zone, circuit and hot-water field. Values, value types, units, register reads and setter keys are unchanged. Consumers read the new names in the same wave. The published GraphQL, MCP and Portal names change, so the gateway binary changes.
