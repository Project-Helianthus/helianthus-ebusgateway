## Provisional config setter keys marked; boiler 0x4904 key takes its documentation name

The `set_boiler_config` key for B509 register 0x4904 (GraphQL mutation `set_boiler_config` and MCP tool `ebus_v1_semantic_boiler_status_set_config`) changes from `installerMenuCode` to `central_heating_pump_mode`, the documentation name of that register. The documentation marks this name provisional: the register may instead hold an installer access code, and which devices of the class use which meaning is unresolved. `installerMenuCode` is rejected like any other unknown key, with the sorted list of accepted keys and before any bus request; there is no alias and no normalisation.

Each row of `docs/testing/config-setter-keys.json` now carries the boolean `provisional` and, where the documentation records one, the `open_question` of its register; the former `open` flag is removed, because no key keeps a name other than its documentation name. Provisional keys are `heating_zone_operating_mode` (`set_zone_config`) and `central_heating_pump_mode` (`set_boiler_config`); `heating_partial_load_power`, `dhw_partial_load_power` and `maximum_heating_flow_temperature_setpoint` carry their open questions without being provisional. The format name is unchanged.

The `field` argument of `set_circuit_config`, `set_system_config`, `set_zone_config` and `set_boiler_config` now has a schema description listing the accepted keys and naming each provisional key, and each key with an open question, with the question the documentation records. The descriptions are built from one key table; tests bind it to the key file and to the keys each setter accepts. The naming inventory records the merged zone and system setter keys as their current names; `heating_zone_operating_mode` stays provisional with the documentation's question.

The register, value type, bound (0 to 255), one-byte encoding and write behaviour of the 0x4904 key are unchanged, as are every other key, register, bound, encoding, read-back and the external write policy. The published boiler snapshot field `installer_menu_code` is unchanged. The Home Assistant integration refreshes its copy of the key file in its own change. The gateway binary changes.
