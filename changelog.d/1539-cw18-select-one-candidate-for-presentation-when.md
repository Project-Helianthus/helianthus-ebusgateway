## One presented candidate for a fact with candidates from several sources

A new gateway presentation policy, `policy:gateway-owner-first` version `1.0.0`, chooses one candidate when a fact key carries candidates of several sources: the qualified candidate observed by the asset's owning source, otherwise the only qualified candidate, otherwise none. A qualified candidate carries a value, is qualified, promoted and good, and is evaluated available and fresh. The policy is presentation only and is applied only above one candidate. The semantic view no longer reports a key with an open conflict as exact; its outcome is unknown with the `value_unknown` reason. The semantic Prometheus target and the semantic slot metrics export the selected candidate instead of dropping the fact, and still export no value for a conflicted key. The Prometheus target applies the policy with the owning source its caller names; the runtime names none yet, so there it presents only the single qualified candidate. A metric slot renders the candidate named by the view's one presentation selection of the key, and only when that candidate is the slot's own binding; without exactly one selection it stays withheld. The SunSpec PV presentation no longer fails the whole read when a key has a conflict or two qualified candidates: such a key is selected under the new policy or has no selection. For keys with one candidate every selection, the PV policy identifier, every output and every golden are unchanged (#1539). The gateway binary changes, so affected release evidence must be renewed before the final bill of materials freeze.
