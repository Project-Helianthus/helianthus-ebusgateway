## The gateway allocates resource identifiers from typed anchors

A new package, `internal/semgraph`, allocates the resource identifiers of the semantic graph. A publisher supplies a typed anchor (a native token with its identification scheme, issuer code and canonical token, a native position, or an operator label), and the allocator returns a deterministic identifier: a domain-separated hash over the resource kind and the anchor key, so a restart needs no stored state. An address, a routed unit number, an entity address path, a credential or certificate fingerprint, a pack class, a profile selector, a display name and an index that is not local to the parent are refused as anchor sources. An anchor upgrade or a revised token form keeps the identifier through a recorded supersession, which refuses a downgrade, a kind or class change and a key already held; resolution refuses an anchor of another class than its key's current one and a raised basis, which rises only by supersession; the supersession table sits behind a store interface with an in-memory implementation. The allocator also records the one home asset of each resource. Tests cover the seven identity events of the graph contract, and `internal/semgraph` joins the protected semantic owners of the import boundary. No publisher uses the allocator yet, so every publisher output, golden, MCP result and GraphQL result is unchanged (#1539).
