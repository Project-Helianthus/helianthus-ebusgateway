## Choose graph enforcement per hub asset and report which families are in the graph

A semantic hub declaration can now ask for a graph-enforced kernel: `AssetSpec.Graph` and `ClassSpec.Graph` build the asset's kernel with the element catalog compiled into SemReg, which loads only when its digest is SemReg's pinned digest. A declaration whose packs the catalog does not cover fails with `membership_missing` and claims nothing; a declaration without the flag builds its kernel exactly as before and still refuses every graph member; the choice cannot change after declaration, and a contributor of an enforced asset publishes under the same rules. `Hub.GraphState()` lists every declared asset as `enforced` or `not_enforced` and reports the element catalog digest once, for the release bill of materials. One gateway table names, per composed family (EVSE, PV, storage, thermal), whether its declarations ask for enforcement; every family is off, so every publisher output, golden, MCP result and GraphQL result stays the same. The startup preflight also calls two empty composition seams, for family pairings and operator records, once each (#1539).
