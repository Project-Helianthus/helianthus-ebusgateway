## Carry operator identity declarations in the batch of the driver whose binding they name

The semantic publication hub now keeps, per asset and publishing source, the operator identity declarations that only a driver's own batch can publish: an identity link stating that the binding observing a given native resource observes a given resource, with the declaration's audit evidence as its basis (`Hub.SetOperatorLinks`). A declaration names the binding's native resource, so it survives a generation fence and the successor's binding of the same native resource carries it. A transaction exposes the links still to be published, including the withdrawal of a link that is no longer declared, through `Tx.OperatorLinks`; an adopting publisher replaces its own link of each returned binding with the returned one. `Commit` refuses with `ErrOperatorLink` a batch whose operator links (links whose basis holds operator declaration evidence, or that replace a published operator link) differ from that pending set, so a driver cannot publish an operator basis no operator declared, alter a declared link, or overwrite a published one. A batch that carries no operator link is accepted and leaves the declarations pending. No publisher adopts the accessor yet and nothing is declared, so no published output changes (#1539).
