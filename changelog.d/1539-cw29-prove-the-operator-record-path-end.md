## Prove the operator-record path end to end and document its limit

A new acceptance test (`cmd/gateway/operator_record_acceptance_test.go`) follows operator records of synthetic families from the Portal configuration document through the configuration provider to the snapshots and a graph cut. A pairing homes one operator-slot view of a meter in each of two configuration-only homes, and the cut flags the pair `same_unit`. A configured `measures` relation is published on the driver's asset and is a qualified, `coherent` edge. A record added while the driver's generation is fenced is published, and a record removed while the driver is stopped is withdrawn. An intent on the measured EVSE is refused (`ambiguous_route`) until the driver publishes its own qualified control capability; it is then admitted on the driver's route. A pairing that joins two native observations with different native slots is refused with `identity_drift` and changes nothing. An operator identity link stays pending until the driver's next batch carries it. `docs/architecture/operator-records.md` now describes these scenarios and that remaining limit, and names the Portal operator-record section as the source of the records. No production code changes (#1539).
