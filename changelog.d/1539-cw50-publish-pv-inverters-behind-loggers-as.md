## Publish PV inverters behind loggers as resources with allocated identifiers

Each inverter child read behind a Huawei SmartLogger or S-Dongle now publishes, in its home asset, its PV system, its inverter and a DC input at each native string index with a present voltage or current, as resources whose identifiers the gateway allocates through the process's one resource allocator, together with the gate's system-to-inverter and inverter-to-input relations and identity links that name the observed resource (#1539). Every fact's resource dimension value is now the identifier of its subject instead of text built from the asset identifier or the string index; the lifetime energy counter stays on the PV system the gate gives the child. Each child incarnation observes the inverter and the PV system through one binding each, so the binding headroom of an asset is used two at a time. A driver restart, a new source epoch and a changed endpoint address keep every identifier; a unit the native owner reports as another one at the child gets a new inverter and new inputs, the replaced ones are retired, earlier readings of the child are withdrawn, and the PV system keeps its identifier. The allocator keeps its anchor table beside the runtime state file when composed with it and in memory otherwise. The logger-attached PV family has its own entry in the graph table, switched on; the SunSpec PV class keeps its entry off. The Prometheus semantic target derives a graphed fact's dimension label from the subject resource's kind and, for a phase, its slot, never from the identifier; a snapshot without resources is read as before, so its output is unchanged. The PV mapping gate fetches the re-based public gate and checks its resource identity, anchors and relations instead of the derived-asset form. Values, units and quality of every fact are unchanged; the MCP, Portal and Prometheus goldens are unchanged. Home Assistant entity identifiers built from the logger children's dimension values change; the integration follows separately.
