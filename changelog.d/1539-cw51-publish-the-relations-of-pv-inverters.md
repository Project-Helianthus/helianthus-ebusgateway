## Publish the relations of PV inverters behind loggers and the logger as relaying equipment

The PV family read behind a logger or a dongle now publishes its relations under the re-based PV gate. Every published inverter child keeps its `pv.relation.system_inverter` instance and one `pv.relation.inverter_input` instance per published input, each with basis class `gate_rule`, a basis reference that names the gate row and its rule scope, and a native origin on the binding that observes the starting end. Before a batch is offered, the publisher checks every relation instance against the gate's table: an instance whose definition, basis class or end kinds the gate does not state, or whose basis comes from an index, a label or an operator origin, is refused as a false join; an instance to a resource the publication has not published is refused as a dangling endpoint. The logger of each configured instance is published as `resource.equipment` on the operator slot of the instance label, in its own asset declared by the family's class, with a binding of the gateway path and a qualified identity link that names it. The `relation.relays` instances from the logger to each published inverter are withheld for now: the pinned SemReg names a relation definition only by a pack reference, so the core `relays` definition cannot be named in a record. The publication records that reason, and the relays instances start once the kernel resolves that definition. A withheld child, or one that a complete listing no longer names, keeps its system, inverter and input records as `withdrawn` under the same identifiers instead of leaving no record. No absence statement is published, because the gate states none, and the publisher refuses one. Re-admission makes the same identifiers current again, and a replaced inverter withdrawn in this way is retired. Retiring an epoch removes every gate-rule instance in the same snapshot and keeps the operator-origin resources current. Child and logger batches now carry the hub's pending operator identity declarations through the transaction accessor, and a successor epoch carries them again. A declaration that still names a retired inverter is not installed on the replacement binding: the qualified link of that binding observes the new inverter, and the replacement batch commits. Instance status lists the logger asset once that asset is published. Every instance is `coherent` in a complete hub cut, and one unit reached through two configured labels stays two unjoined inverters (#1539).
