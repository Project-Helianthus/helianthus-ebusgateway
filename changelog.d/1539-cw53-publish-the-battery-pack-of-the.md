## Publish the battery pack of the low-voltage BMS family over RS-485 as a resource

The storage publisher of the low-voltage BMS family over RS-485 now publishes its battery pack as a `resource.battery_pack` resource whose identifier the gateway allocates through the process's one resource allocator, homed in the configured storage asset (#1539). As the re-based storage gate states, the pack is equipment anchored on an operator slot from an operator label: the slot is a domain-separated digest of the label the operator configured for the storage, with an operator origin, no identification scheme and no parent. Every fact's `storage.dimension.pack` value, every projection source key, the identity link and the pack service now name that identifier instead of the asset identifier. The identifier depends on the label only, so a driver restart, stop then start, a new source epoch, another source identifier and another unit number keep it, and two labels never share a pack. The gate states no relation and no absence, so none is published. Soft start still withdraws only the publisher's own operating-state candidate and leaves the pack current. The storage family's graph table entry is switched on, so the storage asset's kernel is graph-enforced and refuses a fact that names a pack the asset does not publish. The Prometheus semantic target takes the `pack` label from the subject resource's kind instead of special-casing the dimension, so its output is unchanged, and a pack value that names no battery-pack resource is never exported. The storage mapping gate pins the public storage gate re-based on resources. Fact values, units and quality are unchanged; the storage goldens change only in the pack dimension value and the graph records and digests that follow from it.
