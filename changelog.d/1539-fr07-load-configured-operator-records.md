## Load configured operator records and accept an identity link

Startup loads the operator-record section the configuration already holds, including an identity link that names the home asset, the native resource and the configuration basis class. An empty section still admits nothing. Startup does not declare a home the preflight snapshot does not already name, so a driver that discovers that home can claim it; the identifier's shape is not ownership. A home a driver already owns is not declared again. Its configured set is published when that owner has admitted the provider, and it is reported and left unpublished when the owner has not. A set whose home or starting end is not yet there stays pending. A Portal replacement supersedes relations that were waiting at startup, so a relation the operator removed is not published when its home appears. The declaration of a configuration-only home at startup is deferred: the section does not say whether a driver owns a home identifier, so a record whose home no driver declares stays pending and is not published. The provider still does not publish the identity link. It declares the link to the hub for the source whose binding observes the native resource, withdraws that declaration when the section drops the link, and reports the link as waiting with `identity_link_pending`, also when its home holds published records; while no binding observes the native resource, the link waits with `native_unobserved`.
