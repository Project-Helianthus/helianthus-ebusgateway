## Read the eeBUS heating values again and restore them to the GraphQL zone, hot-water and system fields

The gateway reads the eeBUS heating values again and fills the GraphQL and Portal overlay with them: hot-water temperature, target temperature, operating mode, mode-changeable flag and one-time-charge flag; outdoor temperature, gateway brand and gateway vendor; and, per zone, room temperature, target temperature, operating mode, mode-changeable flag and the generic zone label. One inbound reader resolves any number of zones: the n-th room and the n-th heating zone in entity-address order form zone n, and unequal counts resolve no zone. Each value passes the existing source-profile admission before it is read. A cycle whose eeBUS runtime is not ready, or whose remote binding changes, empties the overlay; a value whose admitted read fails keeps its last-known value while the binding stays the same. In the managed start path GraphQL and Portal read the overlay of the worker of the running eeBUS generation, and an empty overlay while no generation runs. A non-null eBUS value still wins over an eeBUS value. The GraphQL schema, MCP and the capture tool are unchanged. The gateway binary changes.
